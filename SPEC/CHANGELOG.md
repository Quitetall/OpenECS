# OpenECS specification changelog

All notable changes to the OpenECS standard. The spec was versioned
independently of the `open-eeg-codec-standard` crate through 0.9.x; from 1.1 the
crate carries the spec's version line. See [`OpenECS-v1.1.md`](OpenECS-v1.1.md)
§11 for the version/stability policy.

## 1.1 — 2026-09-05 (crate 1.1.0)

**No threshold changed.** The tier table is byte-for-byte what 1.0 published;
`tests/spec_thresholds.rs` pins it independently and still passes. A minor
revision under §11.

- **Corpus content identity (§8.2).** A manifest now carries
  `[content_identity] version = 1, digest = <sha256 hex>`: SHA-256 over the corpus
  name/version, the byte-wise-sorted relative paths, each file's exact shape and
  exact rational sample rate (`fs_num`/`fs_den`, §8.2.3), and every decoded `i64`
  sample (per-file `payload_digest`, §8.2.1). No floating-point value is hashed. The
  construction is specified byte-exactly; `tools/content_identity_kat.py` is an
  independent standard-library Python implementation whose known-answer vectors —
  the full pre-hash byte strings, hex-dumped — are frozen in
  `tests/golden/content_identity_kat.json` and re-derived by
  `tests/content_identity_kat.rs`.
- **The ABIR dependency is gone.** 0.9.x computed the corpus identity by projecting
  the corpus into the ABIR data model, pulled from a git revision. The standard is
  vendor-neutral and codec-agnostic; its identity must not depend on one vendor's
  data model, and a public crate must not depend on a git pin. `Cargo.toml` has no
  git dependency; `cargo check --locked` succeeds from a clean clone.
- **Legacy `[abir_identity]` (§8.3).** Read, warned about on stderr by the CLI,
  never verified, never written, never an error — every 0.9.x corpus still grades.
  `corpora/ecs-smoke.toml` ships both blocks for this one release.
- **Smoke corpus identity.** `ecs-smoke` 1.0.0 →
  `93061ae3ef0e74887c90b978f63fc82e46e4e1e17ae249bc826d1d5e60e45e7d`, frozen in
  `tests/corpus_integrity.rs`.
- **`spec_version` is now `"1.1"`** on every report, submission and emitted
  manifest; `openecs emit-corpus-manifest` writes `fs_num`/`fs_den` and the
  content identity. The manifest schema gains the new fields (additive).
- **API (crate 1.1.0, breaking vs 0.9.2).** Removed: `abir` re-exports,
  `CorpusAbirIdentity`, `ABIR_IDENTITY_SCHEMA`, `decoded_signal_content_id`,
  `semantic_content_id`, `semantic_content_id_from_payloads`. Added:
  `ContentIdentity`, `LegacyAbirIdentity`, `payload_digest`, `payload_preimage`,
  `content_digest`, `content_preimage`, `exact_rational`, `hex_lower`,
  `CorpusManifest::{content_identity_of, legacy_warnings}`,
  `CorpusFileEntry::{fs_num, fs_den, sample_rate_rational}`. The projection the
  0.9.x code computed lives on, verbatim, in the LamQuant `eagle` crate
  (`openecs_corpus_abir_content_id`) for anyone who needs the old value.

## Unreleased (folded into 1.1 above)

**No threshold changed.** The tier table is byte-for-byte what 1.0 published;
`tests/spec_thresholds.rs` pins it independently and still passes.

- **Added `SPEC/levels.json`** — a machine-readable export of the tier ladder,
  generated by `openecs levels` and drift-checked against `levels::levels()` by
  `tests/spec_thresholds.rs::committed_levels_json_matches_the_table`. It exists
  because implementers in other languages, and any charting or dashboard code,
  otherwise re-type the floors; a re-typed floor keeps grading against the spec
  revision it was copied from. Pin against this file, not against a transcription.
  Carries `"schema": "openecs.levels/v1"` so a consumer can assert the shape it
  parsed, and `crate_version` so it can record what it graded against.
- **Added `openecs levels`** — prints that JSON on stdout.
- **Added `tools/ecs_admissible.py`** — plots measured `(CR, R)` results against
  the admissible region of each tier and emits a parsable package
  (`verdict.json` with signed per-criterion gaps, `chart.svg`, `summary.txt`,
  `MANIFEST.json` with SHA-256s). Answers "how far from the next tier, and which
  criterion is blocking", which the pass/fail grade alone does not.

## 1.0 — 2026-06-19 (first OpenECS release)

The Open EEG Codec Standard: a vendor-neutral, codec-agnostic benchmark for EEG
compression. (Lineage: extracted and rebranded from an in-house quality
standard; OpenECS v1.0 is the first independent, public release.)

### The standard
- **Five tiers**, strictness order **L < N < C < M < A**:
  - `ECS-L` Lossless — bit-exact (integer-domain PRD = 0), CR ≥ 0.8.
  - `ECS-N` Near-Lossless — R ≥ 0.99, PRD ≤ 5 %, CR ≥ 1.0, no per-band reqs
    (the strongest non-lossless tier; for small-error, not-bit-exact codecs).
  - `ECS-C` Clinical — R ≥ 0.95, PRD ≤ 9 %, CR ≥ 20 + per-band δθαβγ floors.
  - `ECS-M` Monitoring — R ≥ 0.85, PRD ≤ 20 %, CR ≥ 100 + per-band.
  - `ECS-A` Alerting — R ≥ 0.70, PRD ≤ 40 %, CR ≥ 200 + per-band.
- **Codec-conformance contract** (§6): a file-based CLI
  (`encode <in> <out>` / `decode <in> <out> --channels --samples --rate --dtype`)
  that makes ANY codec, in ANY language, gradable with no source integration.
- **Codec manifest** (§7) + **corpus manifest** (§8) schemas (JSON Schema
  mirrors under `schemas/`), and a **results-submission envelope** (§9,
  `EcsSubmission` wrapping per-file `EcsReport`s).
- **Verify-don't-trust** lossless gate (integer-domain exact equality).
- **Optional task-concordance axis** (§10) — codec-agnostic downstream-task
  preservation, reported separately and **out of the tier gates**.
- **Version/stability policy** (§11): SemVer-style; a threshold/metric/L-gate
  change is a major bump. A grader accepts manifests of its major or older.

### Reference tooling (`openecs` CLI)
- `openecs bench` — grade the codec under test + built-in baselines, ranked,
  with a **95 % bootstrap CI** on mean R and a **paired sign-test** p-value vs
  the strongest baseline.
- Parallel, bounded-memory corpus grading (`rayon`) with a live progress bar;
  **median throughput** (citable). Colored unicode-boxed read-out + grade
  badges + sparklines; ASCII charts (`--charts`); a self-contained **HTML
  report** (`--report`, inline SVG, no JS). Real `--help` (clap).
- **ECS-Bench-v1** — the canonical, hash-pinned, publicly-downloadable corpus
  (PhysioNet CHB-MIT subset) under `bench/ECS-Bench-v1/`; an offline synthetic
  smoke corpus (`corpora/ecs-smoke.toml`) is the zero-download default.

### Notes
- Canonical thresholds live in `src/levels.rs` and are pinned by
  `tests/spec_thresholds.rs`. Confidence intervals + significance are derived at
  render time (not stored in the submission). `throughput_mibs` is rounded to
  0.001 MiB/s (stable + JSON-round-trip safe).
